# Use package:graphql

Execute generated GraphQL ASTs with `package:graphql` while keeping typed variables and response parsing generated by Dartpollo.

</header>

## Install both boundaries

Use this integration when you want `package:graphql` transport and normalized cache behavior without the Dartpollo runtime client.

<span class="filename">pubspec.yaml</span>

```yaml
dependencies:
  equatable: ^2.0.8
  gql: ^1.0.1
  graphql: ^5.2.4
  json_annotation: ^4.12.0

dev_dependencies:
  build_runner: ^2.10.0
  dartpollo_generator: ^0.1.0-alpha.7
  json_serializable: ^6.11.0
```

Generated source imports `equatable`, `gql`, and `json_annotation` directly, so generator-only applications declare them directly.

## Configure client-independent generation

<span class="filename">build.yaml</span>

```yaml
options:
  generate_helpers: false
  generate_queries: true
  optimize_document_nodes: false
```

The output includes a `DocumentNode`, operation-name constant, argument classes, and response models, but no Dartpollo import or `GraphQLQuery` wrapper. In `alpha.7`, leave optimization false for this mode.

## Execute a typed query

The committed GitHub `Viewer` operation generates every value required by `QueryOptions<T>`:

<span class="filename">lib/main.dart</span>

```dart
import 'package:graphql/client.dart';

import '__generated__/viewer.graphql.dart';

final link = AuthLink(
  getToken: () async => 'Bearer $githubToken',
).concat(HttpLink('https://api.github.com/graphql'));

final client = GraphQLClient(
  link: link,
  cache: GraphQLCache(),
);

final result = await client.query<Viewer$Query>(
  QueryOptions<Viewer$Query>(
    document: VIEWER_QUERY_DOCUMENT,
    operationName: VIEWER_QUERY_DOCUMENT_OPERATION_NAME,
    parserFn: Viewer$Query.fromJson,
    fetchPolicy: FetchPolicy.networkOnly,
  ),
);

if (result.hasException) {
  throw result.exception!;
}

final viewer = result.parsedData!;
print(viewer.viewer.login);
```

- `document` receives the generated AST. It is already a `DocumentNode`; do not call `gql()` around it.
- `operationName` receives the generated operation-name constant.
- `parserFn` receives the generated response factory.
- `parsedData` returns `Viewer$Query?`.
- `hasException` and `exception` belong to `package:graphql`, not Dartpollo.

The observable result is the current GitHub login through typed `viewer.viewer.login` access.

## Send generated variables

<span class="filename">lib/search.dart</span>

```dart
final variables = SearchRepositoriesArguments(query: 'flutter');

final result = await client.query<SearchRepositories$Query>(
  QueryOptions<SearchRepositories$Query>(
    document: SEARCH_REPOSITORIES_QUERY_DOCUMENT,
    operationName:
        SEARCH_REPOSITORIES_QUERY_DOCUMENT_OPERATION_NAME,
    variables: variables.toJson(),
    parserFn: SearchRepositories$Query.fromJson,
  ),
);
```

`toJson()` preserves generated scalar, input, and wire-name behavior. Check `hasException` before using `parsedData`.

## Mutations and subscriptions

Mutations use `MutationOptions<T>` with `client.mutate<T>(...)`; pass the generated document, name, `variables.toJson()`, and response factory in the same positions.

Subscriptions use `SubscriptionOptions<T>` with `client.subscribe<T>(...)`. The configured link must support the server's subscription protocol; `HttpLink` alone is not a subscription transport.

## Keep cache models separate

`GraphQLCache` is a normalized entity cache. It is unrelated to `DartpolloCachedClient`, which stores whole operation response maps.

Normalized entities still need suitable `__typename` and identifier fields. Interfaces and unions may also require `possibleTypes` configuration in `package:graphql` so abstract fragments normalize and read correctly. Do not layer both cache systems on one request path unless the application deliberately owns two independent invalidation policies.

Continue with the [GitHub tutorial](../guides/github/) for schema preparation and union parsing, or compare the optional [Dartpollo client](../dartpollo-client/).
